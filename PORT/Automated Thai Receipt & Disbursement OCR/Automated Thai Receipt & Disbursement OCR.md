# 📄 Automated Thai Receipt & Disbursement OCR 

> **ขอบเขตการเผยแพร่:** เอกสารนี้เป็นกรณีศึกษาสำหรับ Portfolio โดยไม่รวมซอร์สโค้ดระบบจริง ภาพหน้าจอ เอกสารภายใน หรือข้อมูลผู้ใช้งาน ตัวอย่างข้อมูลใช้เพื่ออธิบายโครงสร้างเท่านั้น รายละเอียดการทำงานอ้างอิงคำอธิบายโครงการและยังไม่ได้ตรวจยืนยันกับระบบจริงในชุดไฟล์นี้


ระบบอัตโนมัติสำหรับสกัดข้อมูลเอกสารทางการเงินภาษาไทย (ใบเสร็จรับเงิน, ใบปะหน้าเบิกจ่าย) ด้วย AI และสร้างไฟล์เอกสาร Word (Docx) แบบสำหรับตรวจทานก่อนใช้งาน

## 📌 บทสรุปโครงการ (Project Overview)
โปรเจกต์นี้ถูกพัฒนาขึ้นเพื่อแก้ปัญหาการบันทึกข้อมูล (Data Entry) จากเอกสารทางการเงินที่มีรูปแบบซับซ้อนและหลากหลาย เช่น บิลเงินสดเขียนมือ, ใบรับรองแทนใบเสร็จรับเงิน, และแบบรายงานการจัดซื้อจัดจ้างของหน่วยงานวิจัย/โรงพยาบาล โดยระบบจะทำงานเป็น Background Process คอยเฝ้าดูโฟลเดอร์ เมื่อมีไฟล์ภาพหรือ PDF ถูกส่งเข้ามา ระบบจะใช้ **Gemini 2.5 Flash** สกัดข้อมูลออกมาเป็น JSON และนำไปจัดหน้าลงใน **Word Template** อัตโนมัติ

## 🚀 ฟีเจอร์หลัก (Key Features)
* **Folder Monitoring Automation:** ระบบทำงานแบบ Watch Folder (สแกนทุก ๆ 60 วินาที) เมื่อเพิ่มไฟล์ลงโฟลเดอร์ ระบบจะประมวลผลและสร้างเอกสารสำหรับตรวจทาน
* **Advanced Thai OCR & Context Understanding:** ดึงข้อมูลชื่อร้านค้า, เลขที่เอกสาร, ยอดเงินรวม, และรายการสินค้า (พร้อมจำนวน) เพื่อช่วยลดการคีย์ข้อมูลด้วยมือ โดยต้องตรวจทานผลลัพธ์ โดยเฉพาะเมื่อเอกสารจะมีทั้งภาษาไทยและอังกฤษผสมกัน หรือเป็นฟอร์มเฉพาะของหน่วยงานราชการ
* **Few-Shot Prompting Strategy:** ใช้เทคนิคการสอน AI ด้วยตัวอย่าง (Few-shot prompting) เพื่อให้ระบบเข้าใจและแยกแยะเอกสารเบิกจ่ายที่ซับซ้อน (เช่น การดึงรหัสโครงการ IO แทนเลขที่ใบเสร็จ หรือการรวมรายการค่าไปรษณีย์หลายวันเข้าด้วยกัน)
* **Template-Based Document Generation:** ใช้ `docxtpl` (Jinja2) ในการนำข้อมูล JSON ไปหยอดลงในไฟล์ `.docx` แม่แบบ ทำให้คงรูปแบบฟอนต์ ตาราง และโลโก้ของหน่วยงานตามแม่แบบ โดยต้องตรวจสอบเอกสารที่สร้างก่อนใช้งาน

## 🛠️ เทคโนโลยีที่ใช้ (Tech Stack)
* **Language:** Python 3
* **AI Model:** Google Gemini 2.5 Flash (ผ่าน `google-genai` SDK)
* **Document Generation:** `docxtpl` (Python-docx Template)
* **Technique:** Automated Document Workflow, Prompt Engineering (Few-shot prompting), JSON Schema Structuring

## ⚙️ โครงสร้างการทำงาน (Workflow)
1. **Monitor:** Python script ตรวจสอบไฟล์ใหม่ (`.jpg`, `.png`, `.pdf`) ในโฟลเดอร์ `INPUT_DIR` (โฟลเดอร์รับไฟล์ที่กำหนดในการตั้งค่า) 
2. **Process:** อัปโหลดไฟล์ไปที่ Google Gemini API และบังคับ Output ให้อยู่ในรูปแบบโครงสร้าง JSON
3. **Validate:** AI คัดกรองว่าเอกสารนี้เป็นใบเสร็จ/ใบเบิกจ่ายที่ถูกต้องหรือไม่ (ถ้าไม่ใช่ จะถูกย้ายไปโฟลเดอร์ Other)
4. **Generate:** นำ JSON Data (เช่น `vendor_name`, `total_amount`) ไปแมปกับตัวแปร `{{ }}` ในไฟล์ `template.docx`
5. **Output:** บันทึกไฟล์ Word ใหม่ที่สร้างเสร็จแล้วลงในโฟลเดอร์ `Word_Docs` และย้ายไฟล์ภาพต้นฉบับไปที่โฟลเดอร์ `Success` เพื่อป้องกันการประมวลผลซ้ำ

## 🧠 ตัวอย่าง Prompt Engineering (Few-Shot Data)
ตัวอย่างข้อมูลสมมติสำหรับอธิบายโครงสร้างผลลัพธ์:
```json
{
  "is_receipt": true,
  "vendor_name": "ใบรับรองแทนใบเสร็จรับเงิน (หน่วยงานตัวอย่าง)",
  "receipt_number": "DEMO-001",
  "items": [
    "ค่าอาหารและเครื่องดื่มสำหรับการประชุมตัวอย่าง/1"
  ],
  "total_amount": 1000.00
}
```
